Secretary Bot

A Secretary Bot is a bot with Secretary Mode enabled, connected to your Telegram account so it can answer private messages on your behalf while you are away.[1]

01

What a Secretary Bot is

A mode, not a separate product

Any bot can become a Secretary Bot: create it with @BotFather, open BotFather’s bot-management web app, and switch on Secretary Mode under Bot Settings → Mode Settings.[1] The bot is then eligible to be attached to your account.

Attached to your account, free

You connect it in your own profile settings under Chat Automation — no Telegram Premium required. It previously lived behind the Premium-only Business Bots menu; Telegram has since made the connection free for everyone.[1]

Working definition for this project. The deliverable is a backend (or constructor logic) behind a Secretary-Mode bot attached to the owner’s account: it sees incoming DMs in the chats you allow, drafts or sends replies under your configured rules, and escalates anything it should not answer alone.

03

Connect it to your account

1

Create the bot

Message @BotFather with /newbot. An existing bot works too — just enable the mode on it — but a dedicated bot keeps secretary behavior separate from anything else.[1]

2

Enable Secretary Mode

Open BotFather’s bot-management web app, pick the bot, and toggle Secretary Mode under Settings → Bot Settings → Mode Settings.[1]

3

Attach it in Chat Automation

In your profile settings (Edit profile → Chat Automation), select the bot, then scope it: which chats it can access — normally only selected chats such as new chats and non-contacts — and which permissions it gets, starting from the Manage Messages minimum.[1]

4

Wire up the backend

Register the bot’s token with your backend or bot constructor. The reply behavior — what it says and when — is defined there, not in Telegram settings.[1]

5

Define the behavior logic

Start with suggested replies (drafts you approve) before full auto-reply: classify intent, pull in context such as buyer or member status, draft the answer, and let the owner approve, edit, or reject it.[2]

04

Implementation plan

Milestone A · connection

  • Create the bot, enable Secretary Mode.
  • Attach it via Chat Automation with the narrowest chat scope.
  • Verify a test DM reaches the backend.
  • Log every incoming message and reply.

Milestone B · suggested replies

  • Classify intent: sales, support, renewal, FAQ, human-only.[2]
  • Attach buyer/member context to each draft.
  • Owner approves, edits, or rejects before anything sends.
  • Track which drafts get edited to improve prompts.

Milestone C · guarded automation

  • Auto-reply only to approved FAQ intents.
  • Everything else stays suggested or escalates.
  • Rate-limit replies; never double-answer one message.
  • Pause switch and full disconnect path tested.

Milestone D · production

  • Stable hosting with health checks and backups.
  • Retention and deletion policy for DM contents.
  • Review queue for escalations the owner must see.
  • Re-check Telegram’s official references — limits here change.[3][4]
05

Constraints to settle before coding

  • Scope: which chats may it touch — only new chats and non-contacts, or more? Default to the narrowest set.[1]
  • Authority: grant the minimum Manage Messages rights; expand only with a reason.[1]
  • Voice: suggested replies first — full auto-reply only for explicitly approved intents.[2]
  • Escape hatch: pause and disconnect must work instantly from the owner’s side.
  • Data: DMs are sensitive — define what is stored, for how long, and how the owner deletes it.
